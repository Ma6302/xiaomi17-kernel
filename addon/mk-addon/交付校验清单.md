
## 4. 四层验证流程（每次改动必须全跑）

```
第 1 层：源码
  在 /sdcard/Download/Operit/kernel-dev/mk-addon/ 下核对 6 项功能

第 2 层：包内  ★ 最容易漏的一层
  unzip -p mk-addon-1.0.0.zip lib/common.sh | grep -c guard_check   # 应=3
  unzip -p mk-addon-1.0.0.zip config.conf | grep ZRAM_ALGO          # 应=lz4
  （不能只验源码目录！）

第 3 层：AK3 内嵌件
  从 AK3 包里解出 mk-addon.zip 再重复第 2 层检查

第 4 层：设备上
  grep -c 'guard_check' /data/adb/modules/mk-addon/lib/common.sh    # 应=3
  tail -10 /data/local/mk-addon.log    # 应见 GUARD: 行
```

**任何一层对不上 = 功能未交付。**

## 5. 改版标准流程

```bash
# ① 改源码（只在权威源目录）
cd /sdcard/Download/Operit/kernel-dev/mk-addon

# ② 打包（必须用 zip 手打，Android 无 zip，用 proot）
zip -r mk-addon-1.0.0.zip module.prop install.sh config.conf \
    service.sh apply.sh collect.sh lib/ -x '*.md'
md5sum mk-addon-1.0.0.zip       # ★ 必须 ≠ 上一版 md5

# ③ 第 2 层验证（包内）
unzip -p mk-addon-1.0.0.zip lib/common.sh | grep -c guard_check

# ④ 装到设备
/data/adb/ksu/bin/ksud module install <路径>/mk-addon-1.0.0.zip
# 注：KernelSU 会放进 modules_update/，需重启生效

# ⑤ 重启后第 4 层验证（设备上）
grep -c guard_check /data/adb/modules/mk-addon/lib/common.sh

# ⑥ 换进 AK3 包（否则下次刷机把旧版推回设备）
#   见下节
```

## 6. AK3 换包流程

```bash
W=/sdcard/Download/Operit/kernel-dev/ak3-fix-<日期>
mkdir -p $W && cd $W

# ① 解出 AK3
unzip -o <旧包>.zip -d ak3/

# ② 替换内嵌模块
cp -f /sdcard/Download/Operit/kernel-dev/mk-addon/mk-addon-1.0.0.zip \
      ak3/mk-addon.zip

# ③ 确认文件名不变（anykernel.sh 硬编码 mk-addon.zip）
grep -n 'mk-addon.zip' ak3/anykernel.sh

# ④ 重新打包
cd ak3 && zip -r -q ../p-new.zip . -x '.*'

# ⑤ ★ 从新包解出来再验（第 3 层）
unzip -o ../p-new.zip mk-addon.zip -d verify/
md5sum verify/mk-addon.zip      # 应与 mk-addon-1.0.0.zip 一致

# ⑥ 替换正式包（先备份）
cp <正式包> <正式包>.bak-old-mkaddon
cp ../p-new.zip <正式包>
```

## 7. 「功能叠加铁律」（事故文档第 8 节）

```
在已有成功版本上加功能时，不许把以前做好的功能丢掉。

做法：
  1. 动手前先列出「上一成功版已经有什么」→ 清单化（见第 3 节）
  2. 加新功能后逐条核对旧功能还在 → 打勾
  3. 每项都用 md5 / grep 实测，不接受「我记得加过」
  4. 源码改动后必须重新打包，核对包 md5 已变
  5. 嵌入 AK3 后从包里解出来再验一次
  6. 刷机后从设备上再验一次
```
